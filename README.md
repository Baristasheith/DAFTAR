# DAFTAR | دفتر

دفتر حسابات عائلي مشترك بالدينار العراقي. Next.js (App Router) + TypeScript + Tailwind + Supabase.
لا ينفّذ تحويلات مالية؛ يسجّل العمليات ويحسب الإجماليات فقط.

## حالة التنفيذ (بصدق)

| البند | الحالة |
|---|---|
| كل الصفحات العشر + إدارة الأفراد + الإعدادات | مبنية، وتُبنى بنجاح (`npm run build`) |
| منطق الرصيد والتواريخ (9 اختبارات) | مُختبر ✅ |
| قاعدة البيانات وRLS والتدقيق وقفل PIN (30 اختباراً على Postgres حقيقي محلي) | مُختبر ✅ |
| الدخول عبر Supabase Auth، وقفل PIN فعلياً، والحفظ والتعديل من الواجهة | **غير مُختبر مع مشروع Supabase حقيقي** — يلزم تنفيذ قائمة الاختبار اليدوي أدناه عندك |
| النسخ الاحتياطي التلقائي | **غير مُفعّل من التطبيق** — يوفّره Supabase حسب خطتك (انظر القسم 6) |

لا تُدخل بيانات حقيقية قبل إكمال قائمة الاختبار اليدوي بنجاح.

## 1) إنشاء مشروع Supabase
1. أنشئ حساباً ومشروعاً جديداً على https://supabase.com (اختر منطقة قريبة).
2. افتح **SQL Editor ← New query**، والصق كامل محتوى `supabase/migrations/0001_init.sql` ثم **Run**. يجب أن تظهر "Success".
3. **Authentication ← Providers ← Email**: فعّله. **عطّل "Allow new users to sign up"** (Authentication ← Sign In / Providers) كي لا يستطيع أحد إنشاء حساب غيرك.
4. **Authentication ← Users ← Add user ← Create new user**: أنشئ حساب المشرف (بريد + كلمة مرور 10 أحرف فأكثر) وفعّل Auto Confirm.
5. **Authentication ← URL Configuration**: ضع Site URL = `http://localhost:3000` الآن، وأضف لاحقاً رابط Vercel، وأضف في Redirect URLs: `http://localhost:3000/auth/callback` ورابط Vercel + `/auth/callback`.

## 2) المتغيرات
من **Project Settings ← API** انسخ:
- Project URL ← `NEXT_PUBLIC_SUPABASE_URL`
- anon/publishable key ← `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- service_role key ← `SUPABASE_SERVICE_ROLE_KEY` (**سرّي جداً**: لا ترسله لأحد ولا ترفعه لـ GitHub)

ثم على Windows (PowerShell داخل مجلد المشروع):
```
copy .env.example .env.local
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```
الصق الناتج في `MEMBER_SESSION_SECRET` داخل `.env.local`، واملأ بقية القيم.

## 3) التشغيل المحلي (Windows 11 + VS Code)
```
npm install
npm run dev
```
افتح http://localhost:3000 ← «ابدأ الآن» ← سجّل دخول المشرف ← تظهر صفحة **الإعداد الأولي** (اسم العائلة + اسمك + PIN) ← لوحة التحكم.

## 4) قائمة الاختبار اليدوي (نفّذها كلها قبل أي بيانات حقيقية)
- [ ] دخول بكلمة مرور خاطئة ← رسالة خطأ موحّدة.
- [ ] دخول صحيح ← الإعداد الأولي ← لوحة التحكم.
- [ ] الإعدادات: ضع رصيد بداية 100,000 ← يظهر في الرصيد.
- [ ] أضف فرداً من «الأفراد» بصلاحيات مقيّدة (مثلاً بلا «رؤية عمليات الجميع»).
- [ ] «تبديل الفرد» ← اختر الفرد الجديد ← PIN خاطئ 5 مرات ← يُقفل 15 دقيقة.
- [ ] بصفة الفرد: أضف مصروف 50,000 ← ظهر اسمه في السجل والرصيد 50,000.
- [ ] اضغط «حفظ» بسرعة مرتين ← عملية واحدة فقط.
- [ ] بصفة الفرد المقيّد: لا ترى عمليات غيرك، ولا ترى صفحة الأفراد/الإعدادات (تحويل للوحة التحكم).
- [ ] عدّل عملية ثم ألغِها ← تبقى ظاهرة بـ «إظهار الملغاة» ولا تدخل في الأرقام.
- [ ] الأرشيف يعرض الأشهر، والتقارير يومي/شهري/سنوي، وتصدير CSV يفتح في Excel.
- [ ] تصدير JSON ثم استعادته على نفس الدفتر ← «أُضيفت 0، تخطي N» (لا تكرار).
- [ ] افتح الموقع من هاتفك بنفس الشبكة وتأكد أن البيانات نفسها.
- [ ] في Supabase ← Table Editor: لا يظهر أي PIN نصاً (فقط هاش يبدأ بـ `$2`).

## 5) النشر على Vercel
1. ارفع المشروع إلى GitHub (**تأكد أن `.env.local` غير مرفوع**؛ `.gitignore` يمنعه).
2. https://vercel.com ← Add New Project ← اختر المستودع.
3. Environment Variables: أضف المتغيرات الخمسة من `.env.example` (واجعل `NEXT_PUBLIC_SITE_URL` = رابط Vercel).
4. Deploy، ثم أضف رابط Vercel إلى Supabase ← Authentication ← URL Configuration (Site URL وRedirect URLs).
5. أعد قائمة الاختبار اليدوي على الرابط المنشور.

## 6) النسخ الاحتياطي — ما هو فعلي وما يحتاج تفعيلك
- **فعلي في التطبيق:** تصدير JSON كامل، واستعادة إضافية آمنة، ومنع الحذف النهائي للعمليات (حتى من قاعدة البيانات).
- **ليس من التطبيق:** النسخ التلقائية لقاعدة البيانات يقدّمها Supabase حسب الخطة (Project Settings ← Database ← Backups). الخطة المجانية لا تضمن نسخاً يمكن الاعتماد عليها.
- التصدير اليدوي ليس بديلاً عنها. صدّر أسبوعياً واحفظ الملف خارج الجهاز، **وجرّب الاستعادة على مشروع تجريبي** قبل الوثوق بها.

## 7) الأمان — ما نُفِّذ
- PIN مشفّر بـ bcrypt (تكلفة 12) ويُتحقق منه على الخادم فقط، ولا يُقرأ من الواجهة أبداً (حتى عبر RLS: العمود غير مسموح).
- قفل بعد 5 محاولات خاطئة لمدة 15 دقيقة (عدّاد ذرّي في قاعدة البيانات).
- جلسة الفرد: كوكي موقّع HttpOnly لمدة 12 ساعة، ومربوط بالمشرف والعائلة، ويُعاد فحص الفرد (فعّال؟ صلاحياته؟) في كل طلب.
- RLS: القراءة فقط لمالك العائلة، ولا توجد سياسات كتابة للواجهة. كل الكتابة من الخادم بعد فحص الصلاحيات.
- سجل التدقيق للإضافة فقط (trigger يمنع التعديل والحذف)، وتدقيق العمليات تلقائي في القاعدة.
- مفتاح service_role لا يوجد إلا في كود الخادم (تم فحص حزمة المتصفح: لا أسرار).

## 8) حدود معروفة
- لا يوجد تحديد معدّل (rate limit) على تسجيل دخول المشرف إلا ما يوفّره Supabase Auth نفسه.
- عائلة واحدة لكل مشرف (حسب التصميم الحالي).
- لم تُختبر واجهة الدخول مع Supabase الحقيقي من طرفي (الشبكة محجوبة عندي)؛ لذلك قائمة الاختبار اليدوي إلزامية.
